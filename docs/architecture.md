# 架构

Python 标准库实现检测执行、平台适配、终端输出与本地 HTTP 服务。React/TypeScript 实现报告界面与浏览器采样。网页无服务端渲染需求，使用 Vite 生成本地静态资源。

## 数据路径

1. CLI 或本地 API 创建 Options。
2. core.runner 以有限并发执行独立检查组，网络组内部同时进行多个出口观测。
   Claude 路由组同时请求两个固定官方域名的公开 trace 接口；时区派生检查在普通网络与 Claude 路由组完成后，按各自 IP 归属生成，避免把普通出口的时区套到 AI 分流上。
3. 每个检查返回 CheckResult，采集代码不直接打印，也不写入配置。
4. Report.to_dict 统一脱敏；文本、JSON、HTTP 和文件导出都使用这一边界。
5. 网页采样在检测后提交到当前报告 ID；后端校验字段及长度，合并为 browser 分组，并刷新已有的时区派生结果。统一的 timezone.advice 优先使用采样浏览器时区，否则仅参考系统时区；普通/API 比较保留为该项 data 内的观测，不再返回三个独立建议。IANA 与偏移均一致显示绿色，差异提示黄色建议；缺数据保留未知。

报告协议版本为 1.0。status 描述检查是否完成，severity 描述完成的检查是否需要核对。unknown / unsupported 不进入成功计数；skipped 独立展示。摘要保留完整度，不生成账号安全评分。

## 本地服务

- 仅绑定 IPv4 loopback，Host 必须匹配服务实际地址。
- API 请求需要每次启动新建的 bearer 凭证；初始网页地址通过 fragment 传递，前端读取后清除地址栏 fragment，并只在本标签页 sessionStorage 保留。
- 有 Origin 的请求必须同源，POST 必须具有同源 Origin。不设置跨域允许头。
- CSP 限制资源和连接为同源，禁止 iframe 嵌入，禁止浏览器向第三方上传检测报告。
- 检测选项和浏览器输入采用允许字段列表、类型/长度与请求大小限制；不提供任意文件读取或任意 URL 查询接口。
- 本地敏感摘要必须通过 `web --allow-local` 允许；网页选择不能绕过启动权限。
- 报告只在内存保留，HTTP 访问日志关闭，响应不缓存，静态文件路径必须位于资源目录。

## 资源与发布

网页资源生成到 Python 包内部的 static 目录，资源不提交到源码 Git。发行时先生成网页资源，再打包 Python；包使用者只需 Python。CI/发布流程应分别执行前端和 Python 验证，发布需用户授权。

## 扩展

检查保持独立函数，外部服务集中在 providers，平台命令集中在 platforms。新增检查时同步协议、文档和测试；若需主动 DNS 验证，应另行定义受控域名/权威解析服务及其隐私边界。

`checks/claude_route.py` 观测固定官方域名的匿名探测，不读取 Clash 控制凭证或修改分流配置。`providers/http.py` 的直连模式仅允许已知公网 IP 的归属查询，不允许用于出口回显或 Claude trace。报告通过各 CheckResult 的既有 `data` 字段记录域名、IP、归属时区及查询路径；协议仍为 1.0。


`checks/ipv6.py` 只读采集 macOS 当前网络服务配置及活动接口地址计数，和 network.ipv6 的外部请求观测独立执行；不会因服务配置 Off 而跳过经代理的出口探测。仅存接口名、配置模式和地址类别计数，不保存 ifconfig 或 networksetup 原文。Clash 文件及控制凭证不在默认采集范围，外部请求不强制直连。

IPv6 回显与 IPv4 回显共同使用受限并发池；IPv6 两个固定服务分别保留观测。network.ipv6 汇总任一有效公网 IPv6、来源覆盖数和多出口差异，全失败时保留 unknown 并提供具体失败原因。输出层不再把具体原因替换为笼统的未完成提示，协议字段及状态枚举保持不变。
