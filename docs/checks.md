# 检测方法与证据

| 检查 | 方法 | 局限 |
| --- | --- | --- |
| IPv4 出口 | 两个 HTTPS 回显服务并发查询 | 仅表示到这些服务的请求路径；单源失败时结果不完整 |
| 本机 IPv6 配置 | macOS IPv4 默认接口对应服务的 `networksetup -getinfo` | 只对明确的 Off 显示已关闭；只代表该服务，无法映射 VPN、命令失败保留未知，其他平台暂不支持 |
| 本机 IPv6 地址 | macOS ifconfig 活动接口 | 只保存公网/ULA/链路本地地址计数与公网地址所在接口；fe80::、回环不当成公网能力，不依据地址存在性断言互联网可达 |
| IPv6 出口探测 | 并发查询 api6.ipify.org / ipv6.icanhazip.com，严格验证公网 IPv6 回显 | 任一成功即可确认该次可达及地址，失败来源单独保留；全部失败显示具体原因；两源 IP 不同提示分流。两者均沿用系统/进程代理，本机经 IPv4 连接代理后仍可由远端访问 IPv6；不等于直连对照或 Claude 路径验证，不推断关闭或泄露 |
| IP 归属 | ipwho.is 查询指定的已观测 IP；默认代理路径失败时尝试归属直连回退 | 记录查询路径，直连不替换被查询 IP；数据库可能过期，多出口时只描述被选中的 IP，不认定住宅性质 |
| Claude API / 网页出口 | 匿名 GET 官方域名 `/cdn-cgi/trace`，验证 `h` 与公网 `ip`，分别查询 IP 归属 | 观测当前进程到该官方域名的路径；不调用模型，不发送密钥或登录凭证，不代表自定义端点或运行中客户端的全部流量 |
| 信誉 | 可选 proxycheck.io / StopForumSpam | 分数与收录不能预测平台风控；错误、限流和缺字段保留为未知 |
| DNS 配置 | macOS scutil、Linux resolv.conf、Windows PowerShell | 不是实际递归解析器或主动泄露测试 |
| 环境代理 | 检查变量是否存在 | 不读出变量值；不能保证连接成功或配置被特定客户端继承 |
| 系统代理 | macOS scutil 解析启用类型 | 其他平台暂不覆盖；配置不代表实际流量路径 |
| 隧道路由 | macOS/Linux 路由表中识别接口名称 | 启发式；不代表全流量覆盖，也不作为风险结论 |
| 时区 | 系统 IANA、TZ、普通检测出口和两个 Claude 同域名探测出口的归属时区分别展示 | 统一为始终显示的“时区建议”，优先比较浏览器（未采样时参考系统）与网页出口；名称和当前偏移均一致用绿色，差异或缺数据用黄色；普通/API 比较存于汇总数据，不单列无需调整说明；Cloudflare colo 不用于推断时区 |
| Claude 端点 | 当前环境及用户 settings 文件 | 逐来源展示，不宣称精确复刻客户端全部设置优先级；不查项目/受管设置 |
| 本地 shell | 可选扫描固定的 shell 配置文件 | 只返回相关变量名与行号，不输出原文；大于 1 MiB 时标记不完整 |
| 账号备份 | 可选在内存比较当前账号与前 100 份备份的 UUID | 只输出数量；缺少比较基准或存在无法读取文件时标记不完整 |
| 遥测文件 | 可选统计 JSON 文件数量 | 不读取事件，不推断上传行为 |
| 浏览器 | Intl、navigator 与可选有限字体比较 | 仅为用户主动打开的这个浏览器的观测，不用于账号风险评分 |

所有网络服务使用固定 HTTPS 目标列表，不使用用户 API Key。Claude 官方域名只允许固定的公开 trace 路径；直连回退仅允许 ipwho.is 的指定公网 IP 路径。网络超时可通过 CLI 配置为 1–15 秒；本地网页采用默认 4 秒。任务进度按检查组完成更新。

归属请求直连回退与出口观测分开：前者只是查询已经观测到的 IP，服务可见其直连来源；ipify、AWS、IPv6 与 Claude trace 探测始终沿用原代理路径。返回 IP 与被查询 IP 不一致时拒绝使用数据。Claude API 和网页观测到相同出口时，本组复用一次归属查询。

结果与导出统一脱敏；首次采集即避免记录秘密值，输出正则过滤只是第二层保护。identity UUID 只在 local 检查函数内用于比较，不进入 CheckResult。


## IPv6 解释与边界

本机网络服务配置、活动接口地址、代理程序的运行配置、远端出口能力应分别核对。Ethernet 的 IPv6 Off 不代表 macOS 所有接口都没有 IPv6；utun 和 fe80:: 地址也不能证明 Clash TUN 开启或具备公网 IPv6。Clash 本地配置文件中的 ipv6、dns.ipv6、tun.enable 只是配置证据，不能代替运行状态；节点可能通过远端网络访问 IPv6。默认检测不读取 Clash 控制密钥，不上传节点配置，不强制绕过代理做直连测试。

展示顺序为本机配置 → 活动地址 → 请求出口，配置关闭与出口未知可以同时存在。外部探测失败仍保留未知与失败原因，不通过关闭配置把失败伪装为成功。

IPv6 外部探测用于观测到指定测试服务的可达性与出口地址。它与 macOS 配置读取、活动地址计数的结果独立。备用来源减少单个检测服务故障的影响；共同的 DNS 或代理策略问题仍可能使两个来源都失败。报告 data.observations 保留每个来源的状态、地址或安全的固定错误消息；至少一个成功时本项 completed 只表示观测到有效 IPv6，不表示失败来源已通过验证。
